AstroArchive user guide
@title About this guide
@category Reference
@summary Which version this guide describes and what AstroArchive needs to run.
Application 3.3.0; package 3.3.0.1.
Windows 10/11 x64; .NET Framework 4.8.

Press `F1` on any page for help with that page. Guide topics stay in English;
the rest of AstroArchive follows your chosen language.

START HERE
@title Getting started
@category Get started
@summary Five steps from a fresh install to a searchable, verified archive.
@walkthrough first-import
@related IMPORT WORKFLOW | USB TRANSFER AND SAVED TELESCOPES | IMPORT OVER WI-FI / LAN
@keywords first setup begin new install quick start
1. Open **Settings → General → Choose repository** and pick the folder for your archive.
2. On **Import**, choose a capture folder and a unique physical telescope ID,
   or use **Connect over network** beside Saved telescope.
3. For a local folder, **Scan folder** and review before importing. For a network
   telescope, connect and select files, **Search all** or **Start live import**.
4. Browse **Repository** by target, search or **Filters**; expand sessions to see subs.
5. Select files and use **Export** for copies, stacking inputs, apps or AstroBin.

> Tip: Imports verify every copy and skip duplicates. Source originals are kept by default.

Stacking and image processing run in your external software.

## Pages
- **Repository** holds your archived captures, grouped by target and session.
- **Edited** keeps working copies and processed results.
- **Import** scans telescopes and folders and copies verified files in.

Switch pages with the purple selector, `Ctrl+1–3` or `Ctrl+Tab`.

## Menus
- **Import / Export** handle files coming in and going out.
- **Repository** holds view options, analysis, backups, maintenance and clean-up.
- **Settings** opens Preferences.
- **Guide** opens this help, Report a problem and About AstroArchive.

Right-click files for preview, metadata, export, working copies or deletion.

## Hints and controls
- Less obvious controls show a short hint when you hover over them.
- Checkboxes show an empty outline when off, a tick when on and a dash when mixed.
- Unavailable controls keep their recorded state and readable labels.

> Tip: Not sure where something is? **Guided fixes** and **Guided tours**, at the top left of this window, walk you through it on the real screens.

- **Accessibility** adjusts text size, rows, contrast and progress animation.

  and scientific exports keep their values.

## Language

Français, Italiano, 日本語 or 简体中文, or follows Windows. It applies after a restart.

- The purple selector switches Repository / Edited / Import; `Ctrl+1–3` selects a page.

> Note: Import dialogs include **Import preferences…**, which opens the Import section while keeping the folders and files you selected.

IMPORT WORKFLOW
@title Import from a folder
@category Import
@summary Scan a folder, review what was found, then copy verified files into your archive.
@walkthrough first-import
@related USB TRANSFER AND SAVED TELESCOPES | IMPORT OVER WI-FI / LAN | PAUSING AND RESUMING IMPORTS | REVIEW, EXCLUSIONS AND DELETION

## Scan and import
1. Choose a saved telescope, or **Browse** to a capture folder.
2. Leave model and camera on **Auto** unless an override is needed.
3. **Scan folder** lists what can be imported. Nothing is copied yet.
4. Check the **Status** and **Review** columns, then **Import**.

Import copies the eligible captures in the filtered view and verifies each copy.
Target analysis defaults to Off.

> Tip: Import greyed out? [Run the guided fix](walkthrough:import-disabled).

## Repeat imports
- Default filename matching skips known captures and completed dated DWARF sessions.
- **Robust file matching** revisits same-name edits, sidecars and missing archive copies.
- **Import → Full rescan** reads and hashes every source file.
- **Cancel** keeps completed imports. Changed sources need a new scan.

## Watch a capture folder
**Import → Watch a capture folder…** (or **Watch folder…** beside Scan folder) imports
captures from N.I.N.A., SharpCap, ASIAIR or other software as they are saved.
1. Choose the folder your capture software writes to.
2. Choose a physical telescope ID.
3. Each file is imported once it stops changing; incomplete FITS are retried.

Earlier captures stay put unless you include them; **Scan folder** imports them later.
Originals stay in the capture folder. Stop watching from Activity at any time.

USB TRANSFER AND SAVED TELESCOPES
@title Import over USB
@category Import
@summary Import straight from a Seestar or DWARF connected by USB, and manage saved telescopes.
@walkthrough usb-telescope
@related IMPORT WORKFLOW | IMPORT OVER WI-FI / LAN
@keywords usb cable drive volume seestar dwarf dwarflab telescope profile device id rename
## Connect and import
1. Connect the telescope so Windows shows it as a USB drive.
2. Choose **Import → Import from Seestar…** or **Import from Dwarflab…**.
3. Choose a saved physical telescope or name a new one.
4. Use **Add folder…** and **Add files…** to pick captures on the telescope drive.
5. Choose **Import**.

- Folders include subfolders; overlapping selections are scanned once.
- Previous selections are remembered for that telescope and volume.
- Selections of 500 or more capture files show a short confirmation first.

> Tip: For faster scans, choose only the target folders you need. **Entire telescope drive** checks every capture folder and can take a long time.

## What happens during a USB import
Every selected capture is fully scanned and hashed, then eligible files are screened
and copied with verification. Saved filename and session shortcuts are bypassed, even
when Robust file matching is off. Import exclusions still apply; rejected or unreadable
captures stay for review.
- Connected imports keep originals and leave analysis off.
- **Cancel** keeps completed copies. Reconnect and select the captures again to resume.

## Manage telescope profiles
- **Import → Telescopes** saves, renames or recovers profiles from archive data.
- **Refresh USB devices** looks again for telescopes connected by USB.
- Recovered profiles need a source association before USB import.
- A physical telescope ID identifies one device; several can share a model.

IMPORT OVER WI-FI / LAN
@title Import over Wi-Fi or LAN
@category Import
@summary Connect to Seestar, DWARF or Celestron Origin over the network and import as you shoot.
@walkthrough network-telescope
@related USB TRANSFER AND SAVED TELESCOPES | PAUSING AND RESUMING IMPORTS | ACTIVITY AND PROGRESS
@keywords wifi wi-fi network lan wireless seestar dwarf origin celestron live hotspot ip smb ftp discovery
## Connect and choose files
1. Choose a repository in **Settings → General** first.
2. On **Import**, click **Connect over network** beside Saved telescope.
3. Put this PC and the telescope on the same network, or join the telescope's hotspot.
4. Discovery starts automatically. Select the telescope and **Connect**; no IP is needed.
5. Choose a saved physical telescope, or keep the suggested new name.
6. **Browse files**, select files or folders, review the total and import.

- Click to select; `Ctrl` or `Shift` adds more; `Esc` clears. Double-click a folder to open it.
- **Search all** selects every supported capture.
- Adjacent sidecars, DWARF session metadata and Origin info.json come with the captures.
- Originals stay on the telescope. Network transfers take longer than USB.

> Note: Celestron Origin keeps individual exposures only when **Save Raw Images** is on in the Origin app (Menu → Settings → Advanced). FinalStackedMaster.tiff is its own stack.

## Import as the telescope shoots
**Start live import** watches the displayed folder and its subfolders. Open one
session or target folder first to limit it, or use **All captures** for the whole storage.
- Before it starts, choose how often to check, the transfer limit, and whether to
  include captures already in the folder (off by default).
- Files must stay unchanged across two checks and through download; incomplete FITS are retried.
- Capture still runs in the telescope app. Keep AstroArchive open and the PC awake.
- Each telescope needs its own saved name; several can run live imports at once.
- **Live import underway** opens Activity, where each watcher has **Stop live import**.
- **Stop all telescope imports** on Import stops every network watcher and download.

> Tip: To catch files captured while AstroArchive was closed, use **Search all** or **Advanced → Also import existing captures**.

## Advanced settings
**Advanced** offers manual IPv4 access, a custom storage path, a discovery adapter,
DWARF FTP credentials, live polling (default 5 seconds) and a transfer limit (default 2 MB/s).
- Passwords are kept only for the active connection.
- Seestar direct access leaves Windows SMB, guest and signing settings unchanged.
- Turn on **Save Each Frame** on Seestar and use compatible firmware.
- Lower the transfer limit if downloads disrupt the telescope.

## If the telescope isn't found
- Check the telescope is awake and both devices share the same network.
- Guest Wi-Fi and client isolation can block discovery. Click **Search** again.
- Find the telescope's IP in its app or your router's device list, then enter it in
  **Advanced** and leave **Storage path** blank.
- Defaults are `\\<telescope IP>\EMMC Images` for Seestar and `/` for DWARF.
- A discovery reply alone doesn't guarantee file access: check firmware file sharing,
  storage path and, for DWARF, the FTP port and credentials.

> Note: Use the telescope's IP address, not this PC's. Windows network settings show this PC's address, not the telescope's.

## Local space and retry
Downloads are staged in `%LOCALAPPDATA%\AstroArchive\RemoteDownloads`. Retry checks their
saved hashes and reuses complete copies, so leave space for these and for the archive.
Stop imports and close AstroArchive before removing caches; completed imports stay.
Read **Reports… → Last import report…** in the bell's Activity panel for errors and warnings.

PAUSING AND RESUMING IMPORTS
@title Pause, resume and recover imports
@category Import
@summary Pause work, resume after a restart or crash, and keep working while imports run.
@related ACTIVITY AND PROGRESS | IMPORT OVER WI-FI / LAN
@keywords pause resume crash interrupted queue stop cancel recover
- **Pause import** keeps your queue and verified copies.
- In **Activity**, pause one telescope or resume a paused or interrupted import.
- **Pause all imports** pauses every active network session.
- **Cancel / Stop** ends the queue instead.

## After closing, a crash or an update
1. Reconnect the original source and telescope.
2. Open **Activity** and choose **Resume**.

Completed archive copies are verified and skipped; an unfinished file restarts from its
beginning. Live-watch baselines are kept, so captures made while paused are still imported.
Source-removal choices from a confirmed file or Dump import stay in effect; USB and network
imports keep originals. Recovery supports folder, USB, network/live, Dump and Edited imports.

## Working while imports run
Settings, filters, grouping and Analytics stay available during network imports.
Preference changes apply to future imports. Switching repository and conflicting file
changes wait until active imports finish or pause. Downloads appear in Import as they
arrive, with an ETA once transfer starts (immediately when a bandwidth limit is set).

DUMP INBOX
@title Dump folder
@category Import
@summary Drop files into the repository's Dump folder and let AstroArchive file them.
@related IMPORT WORKFLOW
@keywords dump inbox drop folder
1. Copy FITS files or telescope folders into the repository's **Dump** folder.
2. Finish copying before AstroArchive checks it.
3. Confirm source removal when asked, at startup or when switching repository.

**Import → Dump folder** also opens or processes it manually.
- Verified science imports and duplicates are removed from Dump; calibration originals stay.
- Changed, locked or failed inputs stay for retry. Other files are left alone.
- Correct Unknown device IDs through **Edit metadata**.

SUPPORTED FILES
@title Supported files
@category Import
@summary Which formats AstroArchive reads, previews and exports.
@related IMAGE PREVIEW AND TABLES | GIF AND VIDEO PREVIEWS
@keywords format fits xisf tiff png jpeg gif ser avi mp4 raw cr2 cr3 nef arw dng codec cfitsio
- **FITS/gzip FITS:** supported HDUs, RGB/Bayer and selected cube slices.
- **TIFF/PNG/XISF:** supported numeric layouts; eligible linear FITS conversion.
- **JPEG/GIF:** display, GIF animation and original-file export.
- **SER:** planetary playback, frame selection and recording export.
- **AVI/MP4/MOV/M4V/WMV/MKV:** Windows-codec playback and original-file export.
- **CR2/CR3/NEF/ARW/DNG:** original import/export; preview needs a Windows codec.

> Note: Tile-compressed FITS needs the optional CFITSIO; Zstandard XISF needs its codec. **Settings → General → Image compatibility** shows what is available and the codec folder.

Scientific decoding has size and layout limits; ordinary exports keep the original bytes.

LIBRARY WORKFLOW
@title Find and select captures
@category Browse and preview
@summary Search, filter, select and group captures in Repository.
@walkthrough missing-files
@related STARS, TAGS AND NOTES | IMAGE PREVIEW AND TABLES | CATALOGUE IDENTITIES
@keywords search filter find select session group subs condensed counter selection query
## Find files
Choose a target or **All Targets**, then search IDs, common names, dates, filenames or
device details. Words combine to narrow results: `M45 Dwarflab`, `M45 S50 Pro`, `M45 stack`.
- Quotes or `file:` search literal filename text.
- **Clear** resets search and filters.
- `Enter` searches immediately; `Escape` clears the search but keeps table filters.

## Search fields
Use `field:value` to search one field: target, file, path, device, camera, filter, type,
format, date, mount, notes, status, review, session and hash (Edited also has source).
- `exposure:>=20 gain:80` compares numbers; exposure is in seconds.
- `-type:Stack` excludes; `OR` or `|` separates alternatives; `*` and `?` are wildcards.
- `"wide field"` keeps a phrase together.

> Tip: Files missing from the table? [Find them with the guided fix](walkthrough:missing-files).

## Select files
- `Ctrl`-click toggles; `Shift`-click selects a range.
- Selections survive target changes. The counter at the top right shows the batch total;
  click it or press `Escape` to clear.
- The path strip shows the repository's total size; hover for captures, Edited, Dump
  and archive data.

## Condensed subs
Repeated Lights share a collapsed session row with dates, count, per-sub exposure, total
integration and filters. Mixed durations show a range; missing values stay unknown.
Expand the row, or turn off **Group subs by session** in **Settings → General**.

**Show starred on top** (same place, on by default) lists starred files above the rest, and starred sessions first among the session rows.
Stacks stay separate. Known counts show Stack (1445); filters still use Stack.

IMAGE PREVIEW AND TABLES
@title Preview and tables
@category Browse and preview
@summary Zoom and pan previews, sort tables and choose columns.

@related CAPTURE DETAILS AND SKY | GIF AND VIDEO PREVIEWS | SUPPORTED FILES

Select a file to preview it in the sidebar; open **Preview image** for a larger window.
On first opening, Repository and Edited select **All Targets** and load its preview;
returning to a view keeps its selection for this session.

## Zoom and display
- Scroll or pinch to zoom; drag or use arrows to pan. **Fit** or `F` recenters.
- `+`/`-` zoom; `Escape` closes the popup.
- Large previews open in source orientation; **Rotate left/right** changes the display.
- **Stretch** changes display values only. Scientific images default to Auto per channel;
  processed and planetary images use Linear.

Sidebars sample still images, normally to 1,400 pixels on the longest edge. Large still
and SER windows decode native pixels within format limits. Repository's preview pane
can be resized by dragging its divider.

> Note: Preview never resizes or rewrites source files.

## Tables and target groups
- Click a heading to sort; click again to reverse. `Shift`-click adds a sort column.
- Right-click a heading to choose columns; drag to reorder. Each page saves its layout.
- Targets show the preferred ID first: M31 - Andromeda Galaxy.
- **All Targets** is bold and shaded; comets share Solar system; Meteors sit above Other targets.
- All Targets orders merged subs, stacks, ungrouped files, then calibrations.
- Individual targets: stacks above lights. Sorts apply within each section.

CAPTURE DETAILS AND SKY
@title Capture details, Stellarium and target circles
@category Browse and preview
@summary The buttons above the preview: capture details, Stellarium and catalogue circles.
@walkthrough sky-wrong
@related OBSERVING TOWN / CITY | ECLIPSES | IMAGE PREVIEW AND TABLES
@keywords details moon elevation altitude phase stellarium target circles overlay info sky map constellation planets
## Capture details (i)
The **i** button above the preview opens Capture details. With a known capture time and
observing town, it lists target and Moon elevations, the Moon's phase and illumination,
and how far the Moon was from the target.

## Stellarium
The **Stellarium** button opens the selected capture's position and field of view, plus
its time and place when known.
- An open Stellarium with the Remote Control plugin is reused; otherwise a new window opens.
- Without Stellarium installed, the same view opens in Stellarium Web in your browser.
- Calibration frames and captures without a position leave the button off.

## Target circles
The target button draws a white circle around every catalogue object in the preview,
labelled with its ID (M 42, NGC 1977) in a break in the ring.
- It is off until you switch it on; switching it off in any preview switches it off everywhere.
- Circles come from the plate solution or the image's WCS header and the built-in catalogue,
  so nothing leaves your PC.
- Captures without a full solution offer **Plate solve…**, which identifies the target first.

## Target information
With no file selected, the sidebar shows the selected target's catalogue overview,
thumbnail and sources, and deep-sky objects get an interactive sky map. Right-click a
target and choose **Show target info**, or press `Escape`, to clear the selection.
- Ambiguous names offer object choices without renaming your files.
- Click a constellation to show its name; click again or press `Escape` to hide it.
- Click the Moon, Sun or target marker (or press `Enter` on the map) for Capture details.

## Times and places
For captures without pointing coordinates, the sky map can calculate approximate Sun,
Moon and planet positions from the capture time. Videos use their capture timestamp.
- A time without a timezone uses your observing town's timezone, including daylight saving.
- A timezone or UTC time in the capture's metadata takes priority.
- The metadata editor can set a capture's timezone explicitly.

ECLIPSES
@title Eclipses
@category Browse and preview
@summary How solar and lunar eclipse captures are recognised and shown.
@walkthrough sky-wrong
@related CAPTURE DETAILS AND SKY | OBSERVING TOWN / CITY
@keywords eclipse solar lunar sun moon obscuration contact
Sun and Moon captures taken during an observable eclipse list under **Solar Eclipse** or
**Lunar Eclipse** in the target list; files and folders are unchanged.
- Solar captures show obscuration on the Sun in the sky map. At 99% or more the Sun is
  drawn with a corona and the capture is tagged **Totality** (remove the tag and it stays removed). Capture details shows the
  percentage of the Sun obscured at capture, a coverage curve with start and end
  times, and the duration of totality or annularity. The Moon's own phase,
  illumination and distance to the target are left out.
- The local Sun and Moon must both be above the horizon for a solar eclipse to show.
- Lunar eclipse details show the same curve and contact times.
- Moon-to-target separation is omitted when the target is the Moon.

## When eclipses don't show
A Sun or Moon predicted below the horizon usually means the target, location, clock or
timezone is wrong.
1. Select the captures and right-click **Edit metadata → Capture**.
2. Set the town / city they were taken in; it can apply to selected sessions.
3. **Use default location** returns to the file's recorded location, then your observing town.

Sky views, horizon checks and eclipse detection follow the saved choice.

CATALOGUE IDENTITIES
@title Target names and aliases
@category Browse and preview
@summary How catalogue IDs, common names and aliases resolve to one target.
@related LIBRARY WORKFLOW | METADATA AND OPTIONAL ANALYSIS
@keywords alias name messier ngc ic caldwell comet planet meteor rename identity
Aliases share an identity: M106, NGC4258, UGC7353 and PGC39600 all resolve to M106.
- Catalogue prefixes matter; M106 differs from NGC106.
- Spacing, accents and full Messier / Caldwell prefixes are normalised.
- Conflicting IDs stay unresolved. Rosette / NGC2244 labels use NGC2237.
- Moon / Lunar and Sun / Solar share labels.
- Planet names in filenames, such as Jupiter or Saturn, resolve to Solar system targets.
- Comet designations and names such as NEAT, LINEAR or NEOWISE group in Solar system.
- Meteor filename labels use Meteor and leave the object ID blank.

## Rename a target
Right-click a target → **Edit name and aliases** saves custom names in app settings.
Names can't claim another object's identity. **Use built-in names** resets that object.

EDITED IMAGES AND WORKING COPIES
@title Edited images and working copies
@category Edited images
@summary Keep processed results and working copies alongside your archive.
@related EDITED METADATA AND EXPOSURE | STACKING PROJECTS AND SESSIONS
@keywords edited working copy processed output version editor photoshop
**Edited** keeps working copies and returned outputs with the repository.

## Add and browse
- **Add images** copies files; **Import folder** scans, with optional subfolders and a review.
- Archived originals and byte-identical Edited files are skipped; changed files can
  become new versions. Unchecked entries leave existing files untouched.
- RAW and scientific types are grouped first by type; GIFs are last.
- Selections stay across targets, searches and refreshes; export includes files selected
  under other targets. Click the counter or press `Escape` to clear.

## Open, export and delete
- **Export → Open in app…** opens working images in your editor. Save outputs alongside
  the working copy; **Refresh** finds them. **Settings → Export** stores app defaults.
- **Export → Files…** copies selected images, verifies their bytes and adds suffixes for
  name collisions.
- **Delete files…** confirms removal of Edited copies. Source originals and archived
  captures stay. Right-click also offers preview, details and file location.

EDITED METADATA AND EXPOSURE
@title Edited metadata and exposure
@category Edited images
@summary How targets, sub counts and total exposure are read and corrected for edited images.
@related EDITED IMAGES AND WORKING COPIES | METADATA AND OPTIONAL ANALYSIS
@keywords exposure integration subs count stacked filename metadata starless
Select images → **Edit metadata** to assign targets, filters, class, exposures, sub counts
or coordinates. Empty or unchanged fields keep their values; files are not rewritten.

## How filenames are read
- `120x60s` means 120 subs of 60 seconds; `30s40` means sub exposure / gain.
- Seestar's `Stacked_36_NGC 7000_5.0s_…` means 36 subs of 5 seconds: 180 seconds in total.
- DWARF's `stacked-16` is bit depth. For recognised DWARF stacks, total integration divided
  by the per-sub exposure gives a count only when it is a whole number. The per-sub
  exposure comes from the filename (`30s40`) or, when the name omits it, from the
  session's `shotsInfo.json` (`exp`); a `shotsStacked` value must agree with the total.
- Starless and Stars only labels are recognised.

## Which value wins
- Explicit header totals and manual corrections take precedence.
- Other unspecified EXPTIME stays reported exposure; it isn't assumed per-sub or total.
- Unknown or conflicting values need review; the Exposure tooltip shows the evidence.
- Sub-summary integration counts acquisition subs only, excluding stacks.

Existing records are repaired on opening, without rereading or moving capture files.

STACKING PROJECTS AND SESSIONS
@title Export and stacking projects
@category Export and stacking
@summary Copy originals, prepare stacking folders or open captures in your processing app.
@walkthrough export-stacking
@related CALIBRATION AND FITS CONVERSION | ASTROBIN ACQUISITION CSV | EDITED IMAGES AND WORKING COPIES
@keywords export stack stacking siril dss deep sky stacker pixinsight copy folder subs app catalogue csv
## Choose an export
**Export** opens one window. Its header counts the files and names their targets; the list
on the left chooses what to make:
- **Files** copies originals.
- **Stacking folder** prepares **Subs**, **Stacks** or **Both**, grouped for stacking.
- **Open in app** verifies copies, then opens them in external software.
- **AstroBin CSV** makes an acquisition table without exporting images.
- **Catalogue CSV** exports metadata for the selection or the whole repository.

Right-click Export items open the same window with that option chosen, and the window
reopens on the option you used last. Folder exports share one destination.

> Note: No app starts stacking automatically. DSS loads file lists; Siril opens the exported folder; other stackers may need you to choose the inputs.

## Optional settings
- Matching calibrations are optional; unknown calibration state needs explicit inclusion.
- **More options** includes separate sessions and rejected-file choices.
- **Add Metadata** and **Create new folder** default to Off. Metadata adds manifests,
  session details and workflow notes.
- Existing files stay; collisions get numbered suffixes.
- Inputs are grouped by target, device, camera, filter, geometry and acquisition settings.
  Different calibration sets stay separate.

## Single-stack handoff

Set its location and export folder under **Settings → Export**. Cancelled or failed

numeric columns keep their values.

CALIBRATION AND FITS CONVERSION
@title Calibration matching and FITS conversion
@category Export and stacking
@summary How darks, flats and bias frames are matched, and converting images to FITS.
@related STACKING PROJECTS AND SESSIONS | FRAME TYPES AND GLOSSARY
@keywords calibration dark flat bias master match temperature convert fits linear
## Calibration matching
Candidates are labelled **Accepted**, **Partial match**, **Needs review** or **Rejected**.
- Values recorded on both files must agree: device, camera, gain, geometry, binning,
  Bayer, offset, readout and filter.
- Darks need matching exposure and temperatures within 3°C.
- A master missing some headers is a Partial match, used only if nothing matches fully,
  and is listed as an export warning.
- Each group gets the nearest-night set (closest temperature for darks).
- Seestar and DWARF flats may come from the nearest night within 30 days.
- Processed subs get no extra calibration.

> Note: Dark flats match raw-flat exposure; don't subtract both bias and dark flat.

## Convert to FITS
**Convert supported images to FITS** is explicit and needs confirmed linear data.
- Selected pages and slices convert physical values without display stretch.
- Originals stay. Cancel keeps verified outputs and removes unfinished copies.

IMAGE QUALITY
@title Image quality scores
@category Analysis and metadata
@summary Score light frames 0–100 against their neighbours and spot clouds, trails and obstructions.
@related METADATA AND OPTIONAL ANALYSIS
@keywords quality score rank fwhm stars clouds trailed clipped obstruction trees exposure fit
**Repository → Review and analysis → Analyse image quality** measures the light frames in
view (or selected) and fills the **QUALITY** column with a score from 0 to 100.
It runs in the background: keep importing, exporting or changing Settings while it works,
and follow it or stop it from Activity. Measurements already made are kept. Deleting the
files it is reading waits until it finishes.

## What a score means
Each sub is compared with similar frames from the same session, so a score says how it
ranks among its neighbours, not how good the night was.
- **Deep-sky:** star size, star count, roundness, noise and obstruction evidence.
- **Planetary and lunar:** edge sharpness, fine detail and noise, plus an
  **EXPOSURE FIT** column (Under, Good or Over) from the Columns menu.
- **Stacks and solar images** are not scored: there are too few comparable references.

Star-poor regions with abrupt background edges can flag a suspected foreground
obstruction (trees, roofs, buildings), and so can a frame whose stars cover clearly
less of the field than its companions'. A partly blocked frame always ranks below every
clear frame it is compared with, however sharp its remaining stars. Smooth gradients
alone don't count.

## Reading the results
- A flag beside a score (Clouded, Trailed, Clipped…) is explained in its tooltip.
- Hover any score for the reasons, or select a capture to see its score, rank and
  measurements in the capture details.
- **Filters → Quality rank** keeps the top or weakest frames, flagged frames or unscored ones.
- Subs inside each session are listed best first when scores exist.

> Note: Scores only suggest. Nothing is rejected or deleted for you.

## What isn't scored
Stacks, solar images, calibration frames, recordings, JPEG and other non-linear or oversized images show `-`;
the tooltip gives the reason. Files found unsuitable while measuring are set aside and
listed in the run report.

Measuring is on demand, or after each import via **Settings → General**. Results are
remembered per file content in the repository's index, so renamed or moved files
aren't measured twice and scores survive program updates. **Analyse image
quality** measures a file again only when the number of captures it is compared
against has changed since; results from an earlier version stay until then.

ARCHIVE SAFETY AND BACKUPS
@title Backups and protection
@category Keep your archive safe
@summary Back up to another drive, restore, schedule backups and protect originals.
@walkthrough backup
@related CLOUD FOLDERS AND BACKUPS | REVIEW, EXCLUSIONS AND DELETION
@keywords backup restore zip incremental schedule protect originals ntfs copy drive
## Create a backup
1. Choose **Repository → Back up archive…**.
2. Pick a folder or ZIP outside the archive, ideally on a separate drive.
3. Close other programs that write to the archive while it runs.

Backups copy images, Edited and the current database, and verify every file.
**Cancel** removes the unfinished backup and keeps earlier ones.

## Restore
**Settings → Backups → Restore a backup…** verifies every file while restoring into a new
folder, then offers to open the restored archive. Restore.txt and backup.json in each
backup also explain the steps and hold checksums.

## Incremental and automatic backups
- The first backup in a folder is complete. Later folder backups share unchanged files
  with the previous one (NTFS hard links), so each stays complete on its own.
- Later ZIPs hold only what changed and restore through the earlier ZIPs they need.
- After a backup, AstroArchive offers to repeat it daily, weekly or monthly; change this
  in **Settings → Backups**. **Keep** removes older backups but never one still needed.
- If the backup drive is missing when a backup is due, Activity reminds you.

## Protect originals
**Settings → Backups → Protect originals** prevents accidental deletion or renaming on
local NTFS drives. Edited, Dump and metadata stay writable.

> Important: Protection is not a backup. Turn it off before moving the archive in Explorer; the Windows owner can still change permissions.

## Review and retry
- **Import → Review and repair** separates rejection, integrity and transfer issues.
- **Reports…** in the Activity panel (the bell) shows the latest scan and import reports.
- Flagged captures are skipped by default. **Retry failed imports** uses the filtered scan;
  changed sources need a fresh scan. Completed imports survive cancellation.

## Exclusions
**Settings → Import** can ignore failed filenames and PNG / JPG / JPEG / MP4 inputs;
rescan after changing them.

## Maintenance and clean-up
- **Repository → Maintenance:** Fill missing metadata, checksum verification, reindexing
  and deletion history.
- **Repository → Clean up:** Delete failed and Purge non-raw files, with Delete archive
  data kept apart at the bottom.

Fill missing metadata previews additions from original headers, recognised filenames
and session metadata. Existing values and your edits stay; conflicting or unsupported
fields stay unknown. Deep-sky and solar-system targets default to Tele when the camera
channel is unknown, recorded as a target-based default.

## Deleting files
- **Delete files** confirms archive-copy removal; source files and shared metadata stay.
- Deletion history blocks reimport of deleted checksums. **Allow reimport** permits a
  later import; it doesn't restore deleted files.
- **Delete archive data** clears indexed captures and managed metadata, keeping Edited,
  source mirrors, unindexed files and deletion history.

## Deleting originals after import
**Delete originals** is optional and only removes verified new or restored source captures.
- Calibration frames (dark, flat, bias, dark-flat and masters) always stay on the source.
- Duplicates and failed clean-ups keep their originals.
- You confirm source removal before the import starts; **Cancel** leaves sources untouched.
- Edited imports always keep source files.

## Recordings
AVI, MP4, MOV, M4V, WMV, MKV and SER use the Video frame type. Their Exposure column
shows recording length in seconds; SER uses its capture timestamp span. In All Targets,
videos appear below still images and above calibrations; within a target, above grouped subs.

HYBRID INFORMATION AND ORBITS
@title Online access and 3D orbits
@category Reference
@summary Choose connectivity, read saved target information and explore native 3D orbits.
@keywords hybrid offline internet cache information comet orbit zoom pan
Setup asks you to choose **Hybrid (recommended)** or **Offline**. Both install
without internet. Hybrid downloads missing information only when you open a target
and saves it for later. Offline uses bundled and saved information. An older or
portable first run asks before making automatic internet requests.

Change the mode in **Preferences → General → Online access**. This also shows
cache usage, a size limit and **Clear downloaded information**. Offline pauses
automatic update checks and downloads; your update and solver preferences stay
saved. Local telescope and Stellarium connections remain available. Internet
links and solving require explicit reconnection through Preferences.

Solar-system and comet pages show **ORBIT** beside Parameters in a wide pane,
or below in a narrow pane. Drag or use arrow keys to rotate in 3D; Shift-drag to
pan. Use +/− or pinch to zoom. The wheel zooms only when the orbit has focus or
Ctrl is held, so the information page remains easy to scroll. Double-click or
press Home to reset.

The picture sits on the real constellations, turned to the ecliptic, with the
orbit plane drawn as a disc with distance rings. Round buttons over it reset,
zoom, look straight down (Top view), look along the orbit (Orbit plane) and
expand the view. The camera glides to each view unless Reduce motion is on.

The target orbit is solid above the ecliptic, dashed below it and fades with
depth. The last stretch it has travelled is drawn bold and ends in a ringed
marker with an arrow along the path, showing where the target is now. Dated
bodies show today; others show their position at the orbit epoch.

Small rings mark where the target was on each date you imaged it; rings that
fall close together are drawn once with a count. Click a ring, or press Enter
in the orbit, for its date. The date opposite the ORBIT heading can be clicked to type another. Diamonds mark the ascending
(filled) and descending (open) nodes, with perihelion and aphelion (or perigee
and apogee).

Planets appear on the same date with a line down to the plane. Body markers are
enlarged and distances use a linear scale, with rings and a scale bar in round
numbers of AU, or kilometres at the Earth–Moon scale.

Open paths have continuation arrows; clipped extents are labelled. Source credits are in the
Sources list at the foot of the page.

Small-body and Moon snapshots use epoch-only markers. Complete elements are
required; an unavailable orbit never receives an assumed orientation.

The view is approximate geometry, not a precision ephemeris or telescope-pointing
tool. Sources show the reference plane, epoch, time standard and solution. Reviewed
information stays authoritative, and failures keep useful local content visible.
Refresh information preserves your scroll position, disclosures and orbit camera.
