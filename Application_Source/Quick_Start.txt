AstroArchive 1.7.0
Windows 10/11 x64 desktop app. Built-in .NET Framework 4.8 and Windows SQLite.
Runs offline. No Python or Google login required.

START HERE
1. Open AstroArchive and choose your archive folder in Settings.
2. Import: choose a telescope or mirror folder and assign a unique device ID,
   such as Seestar-01 or Dwarf-03. Scan folder, review the rows, then import.
   Import options contains model/camera overrides, optional analysis and source
   cleanup. Auto detection and keeping originals remain the defaults.
3. Search either view, then use Filters to narrow target, device, frame type, mount,
   camera, night, session, optical filter, calibration, exposure, gain, dimensions,
   status or review state. Clear resets search and filters without deleting files.
   Import copies only the ready files shown in the filtered view; its button shows
   the count. Hidden candidates remain available for a later import.
4. Select rows with Ctrl/Shift, or use all visible captures when none are selected.
   Right-click selected files, then Export to copy files or prepare a stacking
   folder, with matching calibrations if selected.

USB TRANSFER AND SAVED TELESCOPES
Connect a Seestar/DWARF as local USB storage. In Import captures, select a Saved
telescope or enter its unique physical device ID and model. Browse its capture
folder and press Save telescope. Choose the saved telescope from the dropdown on
later imports. Existing device IDs are recovered from repository records;
Recover from repository adds any missing profiles without replacing your choices.
Recovered profiles need a USB folder association saved before auto upload.

The Auto upload from button appears when a USB telescope source is available.
Click it to screen supported FITS files, skip verified duplicates, import missing
captures and restore missing/damaged archive copies. Originals stay on the USB
device. Solving and rotation stay off for this action. Multiple connected sources
are listed in a menu. Reconnect and click again to resume an interrupted import.
The saved association uses volume identity and survives drive-letter changes.

Rename telescope changes the saved name and matching indexed captures, import
manifests and archive paths in the selected repository. Capture bytes and session
grouping are preserved. Existing names and conflicting destinations are refused.
Failures roll back; an interrupted rename is recovered when reopening the archive.
Keep the local working index/recovery record until that recovery finishes. Other
repositories and previously exported projects retain their existing labels.

IMAGE PREVIEW AND APPEARANCE
Settings > General offers System, Light and Dark themes. The small circle button
in the header switches Light/Dark immediately. The active archive path stays in
the header; choose a different archive in Settings and save.

Select a capture to preview it, or double-click/right-click > Preview image.
The Preview button hides the pane to give the table more room; drag the divider
to resize it. Open image previews a file outside the archive without importing it.
The compact table shows filename, target, type, night, exposure and filter.
Expand Capture details for device, camera, gain, temperature and classification.

Stretch changes the display only; source pixels and FITS headers stay unchanged.
- Linear: no nonlinear stretch; the initial choice for normal raster images.
- Auto: reveals faint data with linked RGB unless colour compensation is needed.
- Strong: a brighter background, with the same automatic colour compensation.
- Auto per channel: independently balance each channel's background.
Auto/Strong compensate for recognised IRCUT/LP filters or a severe RGB cast.
This balances the preview background; it is not a scientific colour calibration.
Solar, lunar and planetary captures use Linear automatically, preserving their
colour. Identification uses the target, observation mode or clear file/folder
names. Correct an unknown target if an unlabelled capture needs this behaviour.
FITS and XISF otherwise start with the saved stretch, defaulting to Auto. Viewing
a solar/planetary image does not change that saved preference. Fit sizes the
preview to its pane; zoom scales the sampled display. Large images are sampled
to roughly 1400 pixels per side, so use an external tool for pixel inspection.

Sun and Solar are one target named Sun. Imports and metadata edits use Sun;
opening an archive also merges existing library labels and cached import records.
New solar imports use Targets/Sun. Existing indexed file paths are preserved.

Preview supports FITS and gzip FITS (integer/float, RGB and recognised Bayer CFA),
XISF mono/RGB/CFA with UInt8/16/32/64 or Float32/64 samples, attached or base64
inline/embedded data, and uncompressed, zlib, LZ4/LZ4HC or byte-shuffled samples.
XISF previews are limited to 256 MB of decoded samples; zstd is unsupported.
TIFF, PNG, JPEG, BMP, GIF and Windows photo formats use Windows image codecs,
including high-depth integer and floating samples when supported by the codec.
DSLR RAW compatibility depends on an installed Windows codec for that camera.
Tile-compressed FITS (.fz), video and multi-frame scientific cubes need conversion.
Archive imports remain FITS-only; previewing other formats does not index them.

IMAGE ZOOM AND TABLE SORTING
Select one repository file and choose Preview image… from its context menu.
Pinch, use the wheel/trackpad or the zoom buttons; drag to pan. Fit (or F)
recenters the image; Escape closes the preview. The gesture viewer uses the same
colour decoders and display stretch as the preview pane. Source pixels stay intact.

Click a column header to sort, click again to reverse, or Shift-click to add
another column. Sorting survives filtering and import/progress refreshes.
Exposure, gain, temperature, dimensions and performance fields sort numerically.
Missing metadata appears as a dash; unknown targets retain Unknown. Bias and
Master bias stay visible under Frame type and in the frame-type filter.

MOSAIC COLLECTIONS
New imports preserve mosaic/project and panel metadata during their existing
header/session reads. Mosaic markers with missing panel information stay
Suggested. Normal mosaic detection does not plate-solve or decode images.

Open Mosaics to review collections, panels, evidence and completed outputs.
Detect from metadata uses selected Library captures, or the visible Library
captures when none are selected. For older archives, Tools > Read headers/session
metadata reads archived headers and preserved session JSON. Existing sky mappings
can suggest adjacent panels and show their outlines; coordinate suggestions need
confirmation. Ordinary target-centre coordinates cannot establish panel membership.

Select captures in Library, right-click > Mosaics > Assign to panel or completed
output. Choose/create a collection and panel, or attach a stitched output.
Collections can span targets, nights, cameras and filters while archive paths and
capture types remain intact. Confirm selected reviews known panel assignments;
assign unresolved captures first. Remove selected retains the decision for later
scans without deleting captures. Tools can edit names, create planned panels or
dismiss a collection. Filters/search include mosaic and panel labels.

Plate solving is optional: select representatives in Mosaics, then Tools > Solve
selected representatives. Cached solutions are reused, and unassigned captures
are solved separately. Complete WCS provides footprints; configured field height
can provide approximate outlines, which are labelled. Target labels are retained.

Export collection creates separate stacking inputs for every panel and compatible
capture group. Completed images go in outputs/completed in Stacks/Both mode.
Choose a collection explicitly when a capture belongs to several mosaics.
Stack each panel first, then stitch the panel results in external software.
Suggested or unresolved assignments must be reviewed before stacking exports.

Keep .astroarchive/index.sqlite and .astroarchive/mosaics/manifest.json with the
archive. The manifest restores stable collection/panel IDs after index loss;
reindexing reconnects captures by hash. Deleted captures remain missing records
in the collection. Archive reset retains collection definitions/deletion history.

WINDOWS FOLDER SELECTION AND GOOGLE DRIVE
All folder selectors use native Windows Explorer dialogs, with This PC, mounted
volumes, an address bar, search and Explorer cloud navigation. Cancel keeps the
existing selection. If a Drive entry is absent, copy the full Windows path from
Explorer and paste it into the selector address bar with Alt+D. The selected
location must expose a filesystem path; a browser-only Drive folder cannot be used.

Select mounted cloud folders in the same way as local telescope folders.
Windows placeholder attributes are detected automatically when available. Cloud
availability time includes opening/reading provider-backed files, which may wait
for a download. Copy + source hash measures local output/hashing separately for
these inputs. The app cannot obtain a reliable Google Drive download percentage,
and provider read time can include cached reads. In Drive/Explorer, making the
input available offline before importing avoids the on-demand download wait.
Cloud placeholder folders are traversed; directory junctions and symlinks are skipped.

The working SQLite index is local to your Windows user, even when the archive is
on Drive. Verified snapshots are written to .astroarchive/index.sqlite inside the
archive. Keep that folder with the FITS files when moving/backing up the archive.
A blocked snapshot is reported while the local committed index remains available.
The live Google Drive/Windows selector integration has not been tested here.

IMPORT PROGRESS, PERFORMANCE AND RECOVERY
Progress and elapsed time start before scanning or file preparation. Discovery
continues while up to two local metadata workers inspect files; streamed/cloud
files are detected automatically; explicit cloud-mode jobs use one worker. A local spill inventory lets traversal
finish without waiting for every metadata read. Until traversal finishes, the
number discovered is provisional and the ETA says estimating.

Imports, selected-file exports and stacking-project copies update progress inside
large files, including SHA-256 destination verification. ETA uses recent progress
and learns the different costs of copying, verification and optional source
cleanup. Compatible prior timings seed a provisional estimate marked ~. Provider stalls show a waiting state;
final index and manifest work show Finalising rather than a completed timer.
The timers describe filesystem work by AstroArchive. A cloud provider may continue
uploading after local copies have completed.

Expand Performance details for discovery, header open/read, classification,
session metadata, duplicate checking, copy/hash, verification and checkpoints.
Overlapping stages are not additive; byte counters describe app reads/writes,
not measured physical disk or network traffic. Gzip parsing counts decoded bytes.
External solver/database reads are not observable.

Shared session JSON is loaded once per scan. Trusted unchanged local headers
can be reused on a later scan before import; session metadata and model/camera
choices are applied again. New source hashes are calculated while copying.
The destination is read back and verified before each record commits. Name,
size or mtime alone never prove a duplicate. Source cleanup keeps its final
physical-boundary and checksum checks.

Settings > Copy workers: Auto begins conservatively and reuses a profile for the
source/archive pair, cloud mode and file-size class. Larger jobs sample up to
four smaller size-spread batches at 1, 2, 4 and 8 workers. Trials stop when the
next setting fails or stops improving throughput. Very large files are excluded
from the pilot. Fixed worker choices remain available in Settings.
Workload, caching, storage and provider delays affect results.

Temporary file locks and provider I/O errors get limited retries. A failed file
is shown with its full path, exception/error code and reason; later files continue.
Disk-full errors stop the batch. Completed imports remain committed. Report opens
the diagnostics, also saved in .astroarchive/reports/last-import.txt. Free space or
resolve the reported source problem, scan again and import to resume. Interrupted
exports retain INCOMPLETE.txt; create a fresh project after an interrupted export.

SCREEN TELESCOPE FAILURES
Screen for failures is available in Import and the capture library. It checks the
visible import rows, or selected library files (all visible when none are selected).
Failed/rejected filename and folder markers, FITS STATUS/CAPSTAT/IMGSTAT failure
values and REJECTED flags appear as Needs review with a reason. Obvious markers
are also flagged during scanning. Screening reads the full supported FITS image,
including compressed data, and checks archive checksums for current files.
Use Filters > Review > Needs review or Rejected / reference to inspect captures,
or No issues flagged to leave them out of an import. Screening does not delete
files or judge star quality, tracking, cloud cover or exposure quality. Rejected
captures remain excluded from stacking by default. Review flags persist in the index.

FAILED FILENAMES
Import options > Ignore failed skips FITS filenames containing "failed" anywhere,
regardless of case, before image data is read. This saved option applies to folder,
USB auto uploads and Dump imports. Ignored files stay in their source folders;
counts appear in scan and import summaries. Change the option and scan again to
refresh the import list. It is off by default. Folder names, target labels and
failure statuses do not affect this filename rule.

Repository tools > Delete failed searches all indexed captures in the active
repository, across filters and telescope selections. Review the matching files
and confirm to remove their repository copies. Originals and shared metadata stay.
Deleted checksums enter deletion history and future uploads skip those captures.
Cloud-synced deletions propagate. This action has no undo.

DELETION HISTORY
Deleting library files records their SHA-256 checksums, UTC deletion times and
original metadata. Future scans show matching captures as Deleted and exclude them
from import, including renamed copies or imports directly from a telescope.
Changed content at the same filename remains eligible. Repository tools > Deletion
history shows the log. Keep .astroarchive/index.sqlite with the archive: it includes
the deletion history and works after a portable restore. Archive reset also retains
this history so clearing an archive does not silently repopulate it on the next scan.

ORIGINALS AFTER IMPORT
Delete originals after verified import is OFF by default and resets after scans
and imports. Only newly copied/restored FITS are eligible. Before removal, the app
saves the archive snapshot, checks the source stamp again, opens both files with
Windows handles, resolves physical boundaries, and compares their SHA-256 hashes.
A changed file, duplicate, overlapping root, identical hard link, lock or cleanup
failure retains the original with a reason. Session JSON, other files and source
folders stay. Deleting a cloud-synced original also propagates through its service.

MAKE, MODEL AND DWARF CAMERA CLASSIFICATION
Metadata and structure are considered per file, including MyWorks, EMMC Images,
Seestar _sub folders, DWARF_RAW, DWARF_DARK, CALI_FRAME and shotsInfo.json. Shared
structures establish the make without inventing an exact DWARF model. Conflicts
remain Unknown. Model/camera overrides and metadata edits are available.

DWARF camera IDs and cam_0 folders identify telephoto; cam_1 identifies wide.
Explicit tele/wide markers are used, including calibration folders. Dimensions or
binning alone do not establish the camera. Conflicting markers remain Unknown.
Telephoto and wide calibration never share export groups or match one another.
This remains a FITS archive. DWARF factory PNG calibration needs conversion to
FITS with the relevant camera metadata or preserved cam_0/cam_1 folder structure.

TARGET IDENTIFICATION AND OPTIONAL ANALYSIS
Identify target first uses unambiguous catalogue IDs/common names in filenames,
such as M33, NGC281 or Heart Nebula (IC1805), without needing a solver. Conflicting
names, HID labels and unrecognised niche targets use the configured plate solver.
Imported captures use the archive copy, so identification works after source removal.

Plate solving and rotation are OFF by default. Import offers:
- Plate solving: Off, Ambiguous only, or All light/stack files.
- Rotation: Off, Ambiguous mounts only, or All light sessions.
Enabling either can take substantially longer. Analysis runs after verified copying,
uses cached results, and uses representative session frames where possible. Plate
solving propagates a result only when additional images match the solved star field.
Manual labels keep priority. Crowded fields and uncatalogued targets need review.

Configure local ASTAP and its star database in Settings, or your Astrometry.net
account/API key. The app bundles a 12,163-object deep-sky catalogue and solver
integrations, but no star database or online account.
ASTAP: https://www.hnsky.org/astap.htm
Wide cameras may need explicit image height in degrees and a suitable star database.
ASTAP uses temporary copies and does not edit the archive/original FITS.
Astrometry.net: https://nova.astrometry.net
The API key is stored with Windows user encryption. Online solving submits detected
star coordinates as a FITS table, not image pixels, and requests non-public submissions.

Rotation uses timestamped acquisition subs, never stacks/registered frames. It samples
up to 18 frames in the longest continuous segment, matches distributed stars and
rejects poor residuals, reflections, scale changes or insufficient coverage. At least
five matches over ten minutes are needed. EQ inference needs observing latitude/
longitude and pointing evidence over at least fifteen minutes where Alt/Az predicts
measurable rotation. Stable orientation without that evidence remains Unknown.
Bad polar alignment, camera movement and registered/derotated data can mislead the
inference. Likely labels remain inferences; reports show measurements/rejections.

STACKING PROJECTS AND SESSIONS
Choose Subs, Stacks or Both. Separate sessions into their own project subdirectories
is OFF by default. OFF combines compatible sessions in each input group. ON creates
sessions/<night>_<session>/subs and sessions/<night>_<session>/stacks, keeping each
session's inputs separate. Subs and stacks always stay in separate folder sets.

Sub groups separate make, physical device, camera, filter, dimensions, binning,
Bayer pattern, exposure, gain and calibration state. Calibration must match every
light in a merged group. Flats require the same night; darks require matching
exposure and known temperatures within 3 degrees C. Already calibrated/registered
lights receive no additional calibration; unknown calibration is flagged and opt-in.
Masters stay separate and require explicit selection in your stacking software.
Do not combine stacks with constituent subs or overlapping live-stack snapshots.
Exports include a manifest and workflow notes. Actual stacking uses external software.

DELETE ALL ARCHIVE DATA
Settings > Archive has a red Delete all archive data button. It shows the selected archive
path and file count. Drag the slider fully right, then press Delete permanently.
Closing the dialog cancels. This removes indexed archive FITS, saved session JSON,
analysis/worker caches and reports. Deletion history, source mirrors and unindexed
files are retained.
Only the selected archive is affected. Cloud-synced deletions propagate and there is
no undo. The repository Clear button remains solely a filter reset.

DUMP INBOX AND DIRECT PROCESSING HANDOFFS
Each selected archive contains a Dump folder. Drop FITS files or telescope folders
there before opening AstroArchive. Startup sorts them into the archive and removes
successfully processed FITS, including verified duplicates. Failed, unsupported,
locked or changed files stay for retry. Session JSON and subfolders stay; metadata
needed by new captures is preserved in the archive. Physical telescope IDs start
Unknown: assign them with Edit metadata before matching calibrations.
Settings offers Open dump folder and Process dump folder now. Finish copying files
before processing. The dump flow has progress/cancellation and saves a last-dump.txt
report in .astroarchive/reports. Normal import cleanup preferences do not affect it.

Select one stack and right-click Export > Send stack to AstroWizard or Siril.
Choose the executable and a working-copy folder outside the archive. The image is
copied, verified and passed directly to the receiving GUI. AstroWizard accepts
.fit/.fits via this route and requires the official signed Clear Eyes Windows build
of 7 October 2026 (verified by checksum). Other builds are refused pending validation.
Siril uses siril.exe, not siril-cli.exe. Gzip, multiple stacks and individual subs
are outside these direct handoffs. StackingWizard incoming handoff and Siril sequence
preparation remain planned; existing ready-to-stack folders are the manual route.

SUPPORTED FILES
.fit, .fits, .fts and .gz variants; primary/IMAGE HDUs; 8/16/32/64-bit integer or
32/64-bit floating data; mono/CFA and up to four colour planes. Tile-compressed .fz,
multi-frame cubes and videos need other tools/conversion. TIFF, JPEG, PNG and
XISF can be previewed; convert them to FITS before archive import.
FITS pixels/headers are never rewritten. Existing export projects are never replaced.
Repository tools index existing FITS, verify checksums and export a CSV catalogue.

VALIDATION
Compiled against Microsoft .NET Framework 4.8 reference assemblies. Generated-data
regressions exercise FITS parsing, streaming scans, SHA-256 copying/deduplication,
per-file failure recovery, caches, repeated checkpoints, DWARF calibration channels,
session exports, archive-reset boundaries, rotation and solver protocol handling.
Windows release builds run application and installer regressions, native file
identity/deletion checks, and WPF smoke checks for themes, previews, saved telescope
selection, filters, live import updates and dropdown scrolling. Physical Seestar/
DWARF USB arrival/removal and live Drive transfers still require real hardware or
provider validation. The ASTAP protocol test uses a test double, not real sky solving.

Attribution and reproducible source are included in AstroArchive_Source.zip.

FILE ACTIONS AND RELEASES
Select files with Ctrl/Shift, then right-click one selected row. Export offers
selected file copies, a ready-to-stack folder, or a ready-to-stack folder with
matching calibrations. The dialog shows available calibration files. Unknown
calibration status requires an explicit opt-in; calibrated/registered lights
receive no extra calibration. Multiple targets get separate folders.
Delete selected files removes only indexed repository copies and their records
after confirmation. Their checksums stay in deletion history. Source copies and
shared session metadata stay. There is no
undo, and cloud-synced deletions propagate. Locked files are reported and retained.
The active repository is a small path at the top. Choose a different repository
in Settings and save to apply it. Settings > Check for and install new releases
checks the stable release. Choose Install release to download and verify setup
inside the application's updates folder, save settings and the archive index,
close AstroArchive, install immediately and restart automatically. The installer
waits for the application and launcher; the restart skips the update check once.
Download or verification failure leaves the app open. A setup failure preserves
the previous installed package and shows an error. Portable copies install at
the registered or default location and retain per-user settings.
